# Issue Template

Use this structure when creating or materially rewriting a roadmap issue. Omit sections that are
genuinely inapplicable instead of filling them with placeholders.

```markdown
## Context

<Why the work exists and the relevant current behavior.>

## Goal

<One concrete outcome.>

## Scope

- <Included change>

## Out of Scope

- <Adjacent work intentionally excluded, when useful>

## Acceptance Criteria

- [ ] <Observable result>
- [ ] <Compatibility or interface requirement>

## Verification

- <Concrete automated or manual check>

## Links

- <Related or parent/sub-task issue, when applicable>
```

The issue must remain understandable without the chat transcript. Keep architecture decisions,
scope changes, verification results, and integration links current as the work progresses.
